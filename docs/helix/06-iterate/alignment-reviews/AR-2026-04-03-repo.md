## Intent Summary

- **Vision**: No standalone vision document exists. The PRD serves as the de facto vision. Dun is a local CLI that discovers and runs quality checks for agent workflows, providing fast, deterministic, agent-friendly output.
- **Requirements**: One command (`dun check`) discovers checks, emits prompt-as-data output, provides fast local feedback, detects doc drift, and enforces Go quality checks. DDx agent service owns harness dispatch; DDx bead service owns work-item tracking.
- **Features / Stories**: 17 specified features (F-001 through F-023) covering auto-discovery, output formats, plugin system, install command, git hygiene, doc reconciliation, automation slider, Go quality checks, exit codes, doc DAG, autonomous iteration, agent quorum, installer/updater, generic command checks, beads routing, doctor command, and check domain model. 5 planned features (F-008 through F-012) have no specs.
- **Architecture / ADRs**: Single Go binary with CLI entry, plugin registry, discovery engine, planner, rule engine, check library, prompt renderer, agent runner, reporter, installer, drift analyzer, change planner, and automation policy. ADR-006 defines the four automation modes. ADR-007 specifies frontmatter YAML canonicalization for deterministic doc hashing.
- **Technical Design**: Solution designs and technical designs exist for all specified features except F-015 (exit codes) and F-022 (doctor). TDs reference user stories via frontmatter `depends_on`.
- **Test Plans**: Test plans exist for all specified features except F-015 (exit codes) and F-022 (doctor). Master test plan identifies 14 P0 critical paths.
- **Implementation Plans**: IPs exist only for later features (IP-013 doc DAG, IP-014 beads routing, IP-015 agent quorum, IP-016 task workflow, IP-023 check domain model). Early features (F-001 through F-007, F-014) were implemented before formal IPs were required.

## Implementation Map

- **Topology**: Single Go module (`github.com/easel/dun`) with `cmd/dun/` (CLI), `internal/dun/` (core), `internal/plugins/builtin/` (embedded plugins: helix, git, go, beads, security), `internal/update/` (self-update), `internal/version/` (version info)
- **Entry Points**: `cmd/dun/main.go` — CLI dispatcher routing 13 subcommands: `check` (default), `list`, `explain`, `respond`, `review`, `doctor`, `task`, `stamp`, `install`, `loop`, `version`, `update`, `help`
- **Public Interfaces**: CLI flags and subcommands; YAML plugin manifests; JSON/LLM/prompt output formats; `dun` frontmatter schema in docs
- **Tests**: 5 packages pass (`cmd/dun`, `internal/dun`, `internal/plugins/builtin`, `internal/update`, `internal/version`). Comprehensive unit test coverage for all check types.
- **Feature Flags / Config**: `DUN_USE_DDX_AGENT=1` env var (delegates to `ddx agent run`); `--automation manual|plan|auto|yolo` CLI flag; `.dun/config.yaml` for coverage thresholds, harness defaults, and model overrides
- **Build / Deploy**: GoReleaser for cross-platform binary distribution; GitHub Releases for distribution
- **Unplanned Code Paths**: `selftest` check type registered but no builtin plugin declares it; `DUN_USE_DDX_AGENT` delegation path is undocumented in `--help`
- **Dead / Orphaned**: `ExitUpdateError = 5` defined but never returned; `--similarity` flag parsed but discarded (`_ = *similarity`); `--format prompt` aliases to JSON (not distinct behavior)
